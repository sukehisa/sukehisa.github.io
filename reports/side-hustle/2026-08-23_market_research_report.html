1. 調査の背景と市場の変曲点

コーディングエージェントの市場は、単一ツールへの依存から複数ツールの併用へ移行しました。 Claude Code は CLAUDE.md、Codex は AGENTS.md、Cursor は .cursorrules をそれぞれ読み込むため、同じリポジトリに対して複数の指示ファイルが並立します。 2026年8月現在、この並立を解消する同期手法（symlink、import、ジェネレータ）は出揃いましたが、同期された指示そのものがコードベースの実態から乖離する問題は未解決のまま残っています。

同時に、Agent Skills の流通量が急増したことで、自然言語の指示書がサプライチェーン攻撃の新しい侵入口になりました。 Snyk の ToxicSkills 調査は 2026年2月時点で 3,984 件のスキルを走査し、13.4% に critical 深刻度の問題を検出しています。

規制面では 2026年8月2日に EU AI Act の透明性義務（Article 50）が発効しました。 チャットボットや AI 生成コンテンツを扱うだけで義務の対象となる一方、2026年4月時点で 78% の組織が実質的な対応に着手していません。

本リサーチでは、この3つの変曲点について Reddit、Hacker News、Cursor Community Forum、Zenn、arXiv、セキュリティベンダーの調査報告から生の声とエビデンスを収集し、5軸評価フレームワーク（満点25点）でスクリーニングしました。

2. 抽出されたビジネスアイデア候補と「生の声」

アイデア 1: agent-rules-doctor (エージェント指示ファイルとコードベース実態の整合性リンタ)

  • ターゲット: Claude Code / Codex / Cursor / Gemini CLI を併用し、指示ファイルを Git 管理しているチーム開発者および個人開発者。
  • 解決する課題: 指示ファイルに書かれた「事実の主張」（実行コマンド、パッケージマネージャ、テストフレームワーク、ディレクトリ構成、CI手順）がリポジトリの実態とズレたまま放置され、エージェントが古い指示に従って誤ったコードを生成する。

検知した生の声（リンク付きエビデンス）

Cursor Community Forum のスレッド「How are people handling context across different AI coding tools?」では、指示の陳腐化そのものが主題として議論されています。

"once context lives only in prompts or memory, it gets stale fast and then agents confidently follow old instructions." — Cursor Community Forum

同スレッドは、乖離が起きる具体的な瞬間まで特定しています。

"Someone renames a script in package.json, moves a config file, switches from pnpm to bun, but AGENTS.md still has the old instruction." — Cursor Community Forum

"A memory like 'we use Jest' survives a migration to Vitest and quietly poisons recommendations." — Cursor Community Forum

複数ツール併用による設定の分岐も同じスレッドで挙がっています。

"You tweak a rule for Cursor and forget to mirror it in the equivalent for Claude Code or Codex, and different tools start behaving differently." — Cursor Community Forum

重要なのは、既存の同期系ソリューションがこの問題を解けていないと当事者が認めている点です。

"Symlinks, imports, and generators automate the sync but leave you with static snapshots that go stale together." — Keep AGENTS.md and CLAUDE.md in Sync Across Agent CLIs

Anthropic 本体の対応状況についても、コミュニティは進展のなさを記録しています。

"Anthropic has not committed to native support, and as of 2026-05-26, the issue is open with no roadmap signal." — Keep CLAUDE.md, AGENTS.md & Cursor Rules in Sync（GitHub issue #6235 は5,200件超のリアクションを集めている）

パターン判定 & Why Now

  • 該当パターン: 6. マイクロDevExツール型 ＋ 4. ワークフロー糊付け・連携型
  • Why Now: 2026年前半に AGENTS.md が事実上のクロスベンダー標準として定着し、「N個のファイルを1個に集約する」フェーズは各種ジェネレータで既に解決済みとなった。次に露出したのが「その1個が実態とズレる」という第二世代の課題であり、まだ専用ツールが存在しない。指示ファイルは Git 管理下のプレーンテキストであるため、LLM を使わない静的解析だけで検証できる点も、原価ゼロで参入できる理由になる。

アイデア 2: skill-audit (Agent Skills / MCP サーバーのローカル・サプライチェーン検査CLI)

  • ターゲット: 外部の Agent Skills やコミュニティ製 MCP サーバーを導入する個人開発者、および導入審査を行う小規模チームのテックリード。
  • 解決する課題: スキルは自然言語の指示書でありながらスクリプトを同梱し、承認済みツール権限をそのまま継承する。インストール前に中身を検査する軽量な手段がなく、悪意ある指示や難読化されたコマンドが素通りする。

検知した生の声（リンク付きエビデンス）

Snyk による初のスキルエコシステム全体監査が、被害規模を定量化しています。

3,984 件のスキルを走査し、13.4% が critical 深刻度の問題（マルウェア配布、プロンプトインジェクション、シークレット露出）を含む。悪意あるスキルの 91% は難読化とプロンプトインジェクションを併用していた。 — The New Supply Chain Frontier: Securing MCP Security and Agent Skills

実害も既に発生しています。

postmark-mcp は実環境で確認された最初の悪意ある MCP サーバーで、エージェントが送信する全メールに攻撃者宛の BCC を密かに追加していた。2026年2月の Sandworm_Mode キャンペーンは npm タイポスクワッティングで Claude Code / Cursor / Windsurf を標的にし、SSH鍵・AWS認証情報・npm トークンを窃取した。 — MCP Security: Risks, Real Incidents & Controls (2026)

レジストリ側の構造的欠陥は、Andrew Nesbitt が個別に列挙しています。

"the user's mental model of 'the agent runs a tool, I approve it' doesn't cover loader commands that run before the agent reaches the prompt." — Skills Registry Threat Models

"A skill the user installed once and forgot about is still part of the prompt, and a description that contains adversarial tokens, hidden HTML, or unicode control characters the loader doesn't strip is a prompt injection that fires unprompted." — Skills Registry Threat Models

"If the user has approved bash, file edit, and network for the session, every skill they install inherits all three." — Skills Registry Threat Models

同記事は既存スキャナの弱点も名指ししています。すなわち、コード実行とプロンプトインジェクションを個別に見るだけで相関させていない点、ロックファイルが名前とバージョンしか記録せずバイト列を固定しない点です。

パターン判定 & Why Now

  • 該当パターン: 6. マイクロDevExツール型 ＋ 5. 規制・プラットフォーム変更対応型
  • Why Now: スキル配布のパッケージマネージャ化（Skilldex 等）が 2026年前半に始まったばかりで、npm が10年かけて整備した provenance・lockfile・cooldown が揃っていない。空白期間のうちに「インストール前に npx skill-audit <path> で叩ける個人向けの一次防衛線」を押さえられる。エンタープライズGRC製品（Snyk, obot, Protego）は導入に営業と契約を要し、個人開発者の手元には届いていない。

アイデア 3: ai-disclosure-guard (EU AI Act Article 50 の実装レイヤー特化ツール)

  • ターゲット: EU 圏のユーザーを持つ小規模 SaaS 事業者・EC 事業者で、チャットボットや AI 生成コンテンツを提供している事業者。
  • 解決する課題: Article 50 は「AI との対話であること」「コンテンツが合成物であること」をユーザーに可視的に示すよう求めるが、既存のコンプライアンス製品は適用範囲診断と技術文書の生成に偏っており、サイトやアプリに実際にラベルを実装する層が空白になっている。

検知した生の声（リンク付きエビデンス）

義務の範囲が中小事業者に及ぶことは、複数の法律実務家が明示しています。

事業者は基盤モデルを構築する必要も高リスクAIを開発する必要もなく対象になる。実装方法によっては、カスタマーサポートのチャットボットから AI 生成のマーケティングコンテンツまで、日常的な利用が透明性義務を発生させる。 — EU AI Act Transparency Rules 2026: AI Labeling Guide

違反には最大 1,500万ユーロまたは全世界年間売上高の3%の制裁金が科され、加えて競合他社からの差止請求リスクが即座に生じる。 — AI Act Article 50: Chatbot and Deepfake Rules for UK Firms

既存製品の価格帯には明確な断層があります。

エンタープライズGRCスイート（OneTrust, Holistic AI, Credo AI）は網羅的だが年額3万〜10万ユーロ超で、商談を経る必要がある。 — Best EU AI Act Compliance Software for Startups (2026)

パターン判定 & Why Now

  • 該当パターン: 5. 規制・プラットフォーム変更対応型 ＋ 3. 価格破壊型

  • 実現可能性 4: Unicode 制御文字・隠しHTML・難読化コマンド・install スクリプトのネットワーク送信を検出するルール群と、それらを相関させるスコアリングの作り込みが必要で、2〜4週間を要する。
  • 収益性 3: セキュリティスキャナは OSS 無料が期待される領域で、有料化はCI連携・組織ポリシー・レポート出力に限られる。企業契約は営業工数を要する。

Idea 3: ai-disclosure-guard — 19点 (Tier 2)

  • タイミング 5: 2026年8月2日発効の直後で、78%が未対応。締切駆動の予算が存在する。
  • 実現可能性 4: サイトスキャナ、開示スニペット、C2PA/IPTC メタデータ埋め込み、証跡ログの4要素で構成され、2〜3週間規模。
  • 収益性 4: 月額€19〜€39 のセルフサーブ価格帯が成立し、100社で月20〜40万円の粗利が見込める。上位のGRCが年額3万ユーロ超という価格断層が味方する。
  • 競合優位性 3: 実装レイヤーは空白だが、Cookie 同意バナー系ベンダーが最も自然に横展開できる位置にいる。参入障壁は高くない。
  • 個人開発適性 3: EU 顧客へのサポート、法改正の追随、証跡保存のためのDB運用が必要で、ゼロインフラにはならない。法的責任の線引きも慎重な文言設計を要する。

4. リスク・反証分析 (Fail-safe Analysis)

1. agent-rules-doctor のリスクと対策

最大のリスクは、指示ファイル中の「検証可能な主張」が想定より少ないことです。 実際の CLAUDE.md の多くは方針や口調の指定で占められ、機械的に真偽判定できる記述はコマンド名とパスに限られる可能性があります。 この場合、検出できる不整合が数件しかなく、ツールを導入する動機が生まれません。

対策として、MVP 着手前に手元の10リポジトリ程度で指示ファイルを実測し、検証可能な主張の平均件数を数えることを推奨します。 1ファイルあたり5件未満であれば、企画を「ドリフト検知」から「指示ファイルの肥大化診断」（300行超・重複・実態と重複する記述の削減提案）へ寄せる判断が要ります。

次点のリスクは Anthropic 本体による吸収です。 /init の再生成や /skill-doctor の延長で同等機能が提供されれば、Claude Code 単独ユーザーは離脱します。 複数ツール併用（Codex、Cursor、Gemini CLI）を前提としたクロスベンダー検証に軸足を置くことで、単一ベンダーの機能追加では代替できない領域を確保します。

2. skill-audit のリスクと対策

セキュリティ製品は、見逃し1件で信頼を失う一方、誤検知が多ければ使われなくなります。 個人開発者が単独で検出ルールの精度と網羅性を維持し続けるのは負荷が高く、Snyk のような研究チームを持つ企業と精度で競うのは現実的ではありません。

対策は、検出精度そのものではなく提示の仕方で差別化することです。 「危険/安全」の二値判定を避け、「このスキルは bash とネットワークを要求し、description に不可視文字を含む」という事実の列挙に徹すれば、誤検知の概念自体が発生しません。 判断はユーザーに返し、ツールは可視化装置として位置づけます。

3. ai-disclosure-guard のリスクと対策

法規制対応ツールの最大のリスクは、事業者が「これを入れれば準拠済み」と誤解し、実際に制裁を受けた際に責任を問われることです。 また EU 圏の顧客に対して日本の個人開発者が信頼を獲得するには、言語と時差の壁があります。

対策として、製品を「法的助言」ではなく「実装補助」として明確に位置づけ、生成する開示文言はすべて出典条文へのリンクを併記します。 販売経路は直接営業ではなく、EU の Web 制作会社やノーコード実装者に対するホワイトラベル提供を第一候補とし、顧客サポートの一次窓口を代理店側に置く設計が現実的です。

6. スクリーニング結果と提案候補 (参考情報)

AIエージェントによる評価・分析結果

  • ゼロインフラかつAPI原価ゼロで、当事者が公然と未解決と認めている課題に直結する agent-rules-doctor（総合21点）を最優先候補として選定しました。既存の同期系ツールが「静的スナップショットが揃って陳腐化する」ことを自ら認めている点が、参入余地の直接的な根拠です。
  • skill-audit（総合19点）は市場の緊急性が最も高い一方、Snyk 等との正面衝突と誤検知リスクを抱えます。「判定せず事実を列挙する」設計への振り切りを前提に再評価する価値があります。
  • ai-disclosure-guard（総合19点）は収益性が3案中最高ですが、EU 顧客へのリーチと法的責任の設計が個人開発適性を押し下げています。ホワイトラベル提供へ切り替えられるかが分岐点です。
